# Post-demo code review — September 2026

Scope: the demo as merged to `main` (commits `chore: project setup` … `docs: README, CLAUDE.md, DECISIONS.md`),
checked against the architecture rules in `CLAUDE.md` and the GDD v1.0.

## 1. Game rules living in `TillWinter.Unity`

| Finding | Verdict |
|---|---|
| `GameController.Update` clamps `Time.deltaTime` to 0.1 s before scaling. | Presentation concern (hitch protection), not a rule. Keep. |
| `PointerInput` owns the tap thresholds (0.2 s, 20 px). | Input concern; the GDD states them under "the ring" but they are about the pointer, not the sim. Keep, but expose as public fields (already are). |
| `HudView.OnHarvested` derives the number of coin sprites from tier and source. | Cosmetic. Keep. |
| `WinterShopView` decides button colour from `CanBuy`/`IsMaxed`. | Reads Core, no rule. Keep. |
| `CameraRig` derives ortho size from grid size. | Presentation. Keep. |

No rule violations found. Every gameplay number is read from `FarmSim`/`FarmConfig`.

## 2. `UnityEngine` leaks into Core

None. `TillWinter.Core.asmdef` has `noEngineReferences: true`, so a leak would not compile.
`[System.Serializable]` on `FarmConfig`/`UpgradeDef` is BCL, allowed.

**GDD conflict (fixed in Session 1):** `FarmConfig.Upgrades` and `CropNames` hold English
user-facing strings. GDD §1 says Core contains no user-facing strings. The Almanac rewrite
replaces them with name/description keys; crops get a `Key` too.

## 3. Tests that assert too little (fixed now)

- `Apprentice_SpeedIncreasesPerLevel` only checked that the level counter reached 3. Now
  measures walked distance at level 1 vs level 3 (0.6 vs 1.0 plots in 0.4 s).
- `Crows_DoNotSpawnInYear1` had a tautological `A || B` assertion. Now asserts the scared
  plot is Ripe and unprotected before waiting 30 s.
- `Config_Defaults_MatchDesignDoc` only re-reads defaults; it will be replaced by the crop-table
  and Almanac-table tests in Session 1.

## 4. Dead code from the demo (removed now)

- `GameController.FingerPlot` and `GameController.Tapped` (nothing consumed them).
- `Prims.EaseOutBack`, `PointerInput.Sample.PressedThisFrame`, `FieldView.Plots`,
  `CameraRig.CamData` (assigned, never read).
- `FarmConfig.CropNames` is unused by the Unity layer; it is replaced by crop keys in Session 1.

## 5. Follow-ups (larger, not done here)

1. **Touch-over-UI detection.** `PointerInput` calls the parameterless
   `EventSystem.IsPointerOverGameObject()`, which is correct for the mouse but unreliable for
   touch with `InputSystemUIInputModule`. Address in the mobile session (S8) using the touch id.
2. **Everything is code-built** (canvas, materials, meshes). Fine per GDD §13 until the visual
   phase; then move to prefabs + TextMeshPro. The `UiKit` helpers should be deleted at that point.
3. **`SmokeTest` finds the Next Year button by GameObject name.** Fragile; give the shop a
   small test hook once the Almanac screen exists (S4).
4. **`FarmSim` uses `System.Random`** for crow placement. Deterministic per seed, but the
   sequence depends on the .NET runtime version. Acceptable for tests; replace with a tiny
   xorshift if save/offline replay ever needs cross-platform determinism (S2).
5. **Coin display lag** (`HudView` subtracts in-flight coins) reads `FarmState.Coins` every
   frame; with many apprentices this is fine, but the pending sum should be reset on Winter so
   a purchase never shows a negative counter for a frame.
6. **`UpgradePlot` cost curve** (`15 × 1.6^n`) is steep; left for tuning, per GDD §15.
